## Architecture Overview

The solution follows **Clean Architecture** (also known as Onion Architecture), which organises code into concentric layers. Each layer only depends on layers closer to the centre — never outward.

```
┌──────────────────────────────────────────────────────┐
│                   ECommerce.API                      │  ← Presentation (HTTP, DI wiring)
│  ┌────────────────────────────────────────────────┐  │
│  │             ECommerce.UseCases                 │  │  ← Application (business orchestration)
│  │  ┌──────────────────────────────────────────┐  │  │
│  │  │          ECommerce.Domain                │  │  │  ← Domain (entities, core rules)
│  │  └──────────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────┘  │
│                ECommerce.Infrastructure               │  ← Infrastructure (EF Core, SQL Server)
└──────────────────────────────────────────────────────┘
```

> **Key principle:** Arrows of dependency point **inward**. Domain knows nothing. Infrastructure and API are the outermost adapters.

## Layer Responsibilities

### ECommerce.Domain
The innermost layer. Contains **only** pure C# — no NuGet dependencies.

| Concern | Detail |
|---|---|
| Entities | `Product`, `Brand`, `Category` — all extend `BaseEntity` |
| Encapsulation | All properties have `private set` (except FK `*Id` fields needed by EF) |
| Identity | `Guid` primary keys, generated by the database |
| Audit | `CreatedAt` (`DateTimeOffset`) and `UpdatedAt` (`DateTimeOffset?`) on every entity |

### ECommerce.UseCases
The application layer. Orchestrates domain objects to fulfil use cases (commands, queries). Currently scaffolded; use cases and interfaces (e.g. `IProductRepository`) live here.

### ECommerce.Infrastructure
Implements persistence using Entity Framework Core 10 with SQL Server.

| Concern | Class |
|---|---|
| Unit of Work | `StoreDbContext` |
| Schema config | `*Configuration` (Fluent API, `IEntityTypeConfiguration<T>`) |
| Migrations | `Migrations/` folder |
| Registration | `DependencyInjection.AddInfrastructure(IConfiguration)` |

### ECommerce.API
The HTTP presentation layer. Hosts ASP.NET Core controllers, middleware, and wires all DI registrations together in `Program.cs`.

```csharp
builder.Services.AddPresentation();          // ECommerce.API
builder.Services.AddInfrastructure(config);  // ECommerce.Infrastructure
builder.Services.AddApplication();           // ECommerce.UseCases
```

## Dependency Rules

The following dependencies are **enforced by architecture tests** and will cause CI to fail if violated:

| From ↓  \ May depend on → | Domain | UseCases | Infrastructure | API |
|---|:---:|:---:|:---:|:---:|
| **Domain**         | —  | ✗ | ✗ | ✗ |
| **UseCases**       | ✓  | — | ✗ | ✗ |
| **Infrastructure** | ✓  | ✓ | — | ✗ |
| **API**            | ✓  | ✓ | ✓ | — |

✓ = allowed &nbsp; ✗ = **forbidden** (test will fail)

## Domain Model

```
BaseEntity
  ├── Id        : Guid
  ├── CreatedAt : DateTimeOffset
  └── UpdatedAt : DateTimeOffset?

Brand : BaseEntity
  ├── Name      : string (unique, max 200)
  └── Products  : ICollection<Product>

Category : BaseEntity
  ├── Name      : string (unique, max 200)
  └── Products  : ICollection<Product>

Product : BaseEntity
  ├── Name        : string (unique, max 200)
  ├── Description : string (max 2000)
  ├── PictureUrl  : string (max 500)  ← future: Azure Blob / Cloudinary
  ├── Price       : decimal (18, 2)
  ├── BrandId     : Guid  ──► Brand
  └── CategoryId  : Guid  ──► Category
```

## Database & Persistence

- **Provider:** SQL Server (via `Microsoft.EntityFrameworkCore.SqlServer` 10.0.9)
- **DbContext:** `StoreDbContext` — auto-discovers all `IEntityTypeConfiguration<T>` implementations via `ApplyConfigurationsFromAssembly`
- **Relationships:** Product → Brand and Product → Category are configured with `OnDelete(DeleteBehavior.NoAction)` to avoid cascading deletes
- **Indexes:** `Brand.Name`, `Category.Name`, `Product.Name`, `Product.Price` are all indexed uniquely

### Running Migrations

```bash
# From the solution root
dotnet ef database update \
  --project ECommerce.Infrastructure \
  --startup-project ECommerce.API
```

## Architecture Tests

Architecture tests live in `ECommerce.ArchitectureTests` and use **NetArchTest.Rules** + **FluentAssertions**.

### Test Categories

| File | What it checks |
|---|---|
| `LayerDependencyTests` | Cross-layer dependency violations (Domain, UseCases, Infrastructure, API) |
| `DomainRulesTests` | Entities inherit `BaseEntity`, private setters, no EF references in Domain |
| `InfrastructureRulesTests` | EF configurations in correct namespace, DbContext naming, migrations location |
| `NamingConventionTests` | Naming patterns: `*Configuration`, `*DbContext`, no `Entity` suffix, no `I` prefix on classes |
| `DependencyInjectionTests` | Each layer exposes the correct `Add*` extension method with correct signature |

### Running the Tests

```bash
dotnet test ECommerce.ArchitectureTests
```

### Adding the Test Project to the Solution

```bash
dotnet sln add ECommerce.ArchitectureTests/ECommerce.ArchitectureTests.csproj
```

### What Happens if You Break the Rules?

Example: if you add `using Microsoft.EntityFrameworkCore;` to a Domain entity, this test fails immediately:

```
Domain_Should_Not_Reference_EntityFramework
  Expected: not to contain items matching the condition
  But found: Microsoft.EntityFrameworkCore, ...
```

This gives the team fast feedback before code reaches code review.

## Getting Started

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- SQL Server (local, Docker, or Azure SQL)

### 1. Clone and restore

```bash
git clone <repo-url>
cd ECommerce
dotnet restore
```

### 2. Configure the connection string

Edit `ECommerce.API/appsettings.Development.json`:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=Stores;Trusted_Connection=True;TrustServerCertificate=True;"
  }
}
```

### 3. Apply migrations

```bash
dotnet ef database update \
  --project ECommerce.Infrastructure \
  --startup-project ECommerce.API
```

### 4. Run

```bash
dotnet run --project ECommerce.API
```

### 5. Run all tests (including architecture tests)

```bash
dotnet test
```

## Contributing

1. Run `dotnet test` — all architecture tests must pass before opening a PR.
2. New entities belong in `ECommerce.Domain/Entities/` and must extend `BaseEntity`.
3. Persistence configuration goes in `ECommerce.Infrastructure/Data/Configurations/`.
4. Business logic goes in `ECommerce.UseCases/` — never directly in controllers.
